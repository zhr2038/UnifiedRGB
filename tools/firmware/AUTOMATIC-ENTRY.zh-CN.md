# 自动进入升级模式与手动后备（新流程说明）

本说明覆盖保留来源规范中旧的“必须手动进入”步骤；不修改原始来源文件。本次仅离线实现和 fake 验证，尚未进行真实自动进入验收；默认硬件禁用、没有安装审核目录。Root 负责独立审核、部署及物理验收。

1. 加载包只检查文件，不访问设备。可明确选择可信保留 2DCB / 0.25 基线（机主确认、既有回执，不是新读取）。选择后准备不会发送 GET12；新鲜 USB 物理绑定不等于重新验证固件基线。
2. 关闭所有其他固件工具并保持关闭，点击 **自动进入升级模式** 并确认。后台先持久化确切任务维护 lease，阻止新键鼠接管，等待所有原会话退出。
3. 仅绑定唯一正常 0B05:1C24 / MI01 / FF00:1 / Input65 / Output65 / Feature0。持久化 transition intent（任务、唯一 run、实际正常身份、编译命令 SHA256、尝试时间），再次检查集合与元数据，独占正常写句柄。
4. 仅发送一次 Windows 65B `00 7B AA 41 53 55 53 AA` 加 57 个零，经中断 OUT；不发 Feature，不用 OLED exchange，不读取正常 ACK，不发亮度/profile/灯光/设置命令。包和 RPC 不能提供命令字节。3 秒写入期限请求取消，但必须继续等待实际写结束并关闭句柄，绝不分离 pending I/O。异常驱动若不完成，任务保持占有与阻止，而不是虚假声称硬截止已安全关闭。
5. 写前启动被动元数据观察，1 秒节奏，最多 30 次且总观察期限 30 秒。见证正常消失后，只接受同一完整 USB LocationPath 上唯一新升级设备。正常/升级 ContainerId 和 USB ancestor 可以不同，分别保留真实身份；不复制、改名或要求跨 PID ancestor 相等。新 pin 使用实际升级身份，既有 R6 inventory/caps/ledger 绑定不放宽。
6. 写结果未知也不重发；只有旧句柄已 join/关闭后，确切观察到新升级角色才可继续。没有明确匹配转换时保留 intent 和维护，显示需要正常重连/审核恢复；禁止通过同一未知上下文再准备、手动后备绕过或发送任何旧正常 HID。准入后的取消不表示没有发生切换，关闭页面也不取消后台任务。
7. 尚未尝试自动进入时可明确选择 **手动进入（后备）**，再按设备既有物理方法进入；观察规则相同。过期 pin 不能续期，必须重新观察正常→升级会话。
8. 元数据只说明预期 boot `02000200`，不是读取结果。旧正常句柄关闭后，未改变的 R6 是第一个 boot report owner，实际检查 82 回复。进入升级不授权备份或擦写；备份/安装/恢复仍各需明确操作、可信软件审核、真实双遍前镜像与完整核验。

库存选择先确定唯一合格 vendor 升级集合，再把完整库存交给原样 R6 校验。同一升级实物的可读键盘集合可以保留；不可读鼠标集合只有在 Windows Mouse 类、硬件 ID、access0 错误 5 及同一升级实物身份全部正向证明时才允许排除。未知、外来、不明确或错误端口仍拒绝。观察器首次采样立即失败或已返回升级结果时，现有写前 gate 会拒绝发送：保留 intent 不表示发过命令，也不建立新 boot owner。请保持 USB 连接，必要时重新连接升级接口。

`.25` 标签不变不能证明 D50 或其他候选已安装，不能复制官方工具的 SameFWVersionSkip；必须依赖原有完整镜像核验。本次不新增 FD/8E、刷后复位或自动退出命令。

设备内部调用原厂 quiesce，其 NVM/设置副作用没有全部证明，不能承诺“零内部副作用”。本地场景、配置、校准与既有备份语义不变。本次证据不授权升级退出、复位或自动刷后回正常。

Host 在最早 gate 工厂、任何设备 owner 建立前，只读检查 `firmware/maintenance-lease.json`。任何 pending 或 malformed lease 都阻止 ROG 接管并禁用固件操作；损坏 lease 报告未知意图、无虚构 GUID，不崩溃整个 Host，也不能通过旧手动 Enter/Exit 清除。
